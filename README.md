# Trabalho Progração Web GA e GB

### 1. Visão Geral do Trabalho
 
O trabalho prático da disciplina consiste no desenvolvimento de um website completo em grupo de até 3 integrantes, abordando progressivamente os conteúdos trabalhados ao longo do semestre: HTML, CSS e JavaScript. O trabalho é dividido em duas entregas, permitindo que os alunos construam e aprimorem o projeto de forma incremental.

#### Entrega 1 (GA)

Prazo: Metade do semestre

Foco: HTML + CSS

Peso na nota: 4 Pontos GA
 
#### Entrega 2 (GB)

Prazo: Final do semestre

Foco: HTML + CSS + JavaScript

Peso na nota: 4 Pontos Grau B

#### Formato Entrega

Publicação via FTP + Relatório 1

Publicação via FTP + Relatório 2
 

### 2. Escolha do Tema
 
Cada grupo deve escolher um dos seis temas listados abaixo. Cada tema traz sugestões de páginas e funcionalidades, mas o grupo tem liberdade criativa para adaptar o conteúdo dentro do tema escolhido. Nenhum tema pode ser repetido entre grupos da mesma turma — a escolha é feita por ordem de chegada.

Caso o grupo deseje trabalhar com um tema diferente dos listados, é necessário submeter a proposta ao professor para aprovação antes de iniciar o desenvolvimento.

#### 2.3 Tema Escolhido (Wiki de Série, Anime ou Filme)

Uma enciclopédia colaborativa dedicada a uma série, anime ou franquia cinematográfica. O site funciona como referência de fãs, reunindo informações sobre episódios, personagens e universo da obra.

#### Sugestões de páginas:

- Home: destaque para a obra com trailer incorporado e últimas atualizações da wiki.

- Personagens: cards com foto, nome, descrição e afiliações de cada personagem.

- Episódios / Temporadas: lista de episódios com sinopse e avaliação.

- Universo / Lore: locais, organizações, tecnologias ou magia do universo da obra.

- Teorias e Curiosidades: seção com fatos interessantes e teorias dos fãs.

- Contato: formulário para sugestão de conteúdo à wiki.

### 3. Entrega 1 - Estrutura e Estilo (HTML + CSS)
 
A primeira entrega corresponde à estrutura e apresentação visual do website, sem a camada de interatividade. Nesta etapa os alunos devem demonstrar domínio de HTML semântico e estilização com CSS.

#### 3.1 Mapa do Site

Antes de iniciar a codificação, o grupo deve elaborar um mapa do site (sitemap), que é um diagrama hierárquico mostrando todas as páginas e a navegação entre elas. 

O mapa deve:

- Ser entregue como imagem (PNG ou PDF) junto com o relatório.

- Identificar claramente a página inicial (Home) e todas as páginas secundárias.

- Indicar os links de navegação entre as páginas.

- Ferramenta sugerida: draw.io, Figma, Canva ou similar.

#### 3.2 Requisitos Técnicos HTML

- Mínimo de 5 páginas HTML distintas.

- Uso de tags semânticas: `<header>`, `<nav>`, `<main>`, `<section>`, `<article>`, `<footer>`.

- Menu de navegação funcional presente em todas as páginas.

- Pelo menos uma página com formulário (contato, pesquisa, cadastro, etc.).

- Uso correto de cabeçalhos hierárquicos (`<h1>` a `<h3>`).

- Imagens com atributo alt preenchido corretamente.

- Links internos e externos funcionando.

#### 3.3 Requisitos Técnicos CSS

- Arquivo CSS externo (não usar estilos inline ou `<style>` no HTML).

- Layout responsivo: o site deve funcionar em desktop e dispositivos móveis.

- Uso de Flexbox ou CSS Grid para estruturar o layout.

- Paleta de cores consistente e identidade visual definida.

- Estilização de formulário, navegação e pelo menos uma galeria ou grade de conteúdo.

- Uso de media queries para responsividade.

#### 3.4 Publicação

O site deve ser publicado em servidor web via FTP, fornecido pelo professor. A URL do site publicado deve constar no relatório.

#### 3.5 Relatório da Entrega 1

O grupo deve entregar um relatório em formato PDF ou DOCX contendo:

- Identificação do grupo (nomes e matrículas dos integrantes).

- Descrição do tema escolhido.

- Mapa do site (imagem incorporada).

- Descrição das páginas criadas e suas finalidades.

- URL do site publicado.

- URL do projeto no GitHub.

- Dificuldades encontradas e como foram superadas.

- Divisão de tarefas entre os integrantes.

### 4. Critérios de Avaliação

#### 4.1 Entrega 1 (4 pontos) 

| Critério | Peso |
|----------|------|
| Mapa do site (clareza e completude) | 10% |
| HTML semântico e estrutura das páginas | 25% |
| CSS: layout, responsividade e design | 30% |
| Publicação correta no servidor web | 15% |
| Relatório (qualidade e completude) | 20% |
| **TOTAL** | **100%** |

#### 5. Regras Gerais
 
- O trabalho é em grupo de 3 integrantes. 

- Plágio ou cópia de outros grupos resultará em nota zero para todos os envolvidos.

- O uso de templates prontos não é permitido. Todo o código deve ser produzido pelo grupo.

- O uso de geradores de código por IA (GitHub Copilot, ChatGPT, etc.) deve ser declarado no relatório, indicando o que foi gerado e como foi adaptado. O grupo é responsável por compreender e explicar todo o código entregue.

- O site deve ser original e conter conteúdo de autoria do grupo (não copiar textos ou imagens sem permissão; indicar a fonte quando usar conteúdo de terceiros).

- Atrasos na entrega estão sujeitos a penalidade de 1 ponto por dia de atraso, até o limite de 5 dias. Após isso, a entrega não será aceita.
